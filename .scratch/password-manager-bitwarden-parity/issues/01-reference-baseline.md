# 01: Verify the reference feature baseline

**What to build:** An evidence-backed comparison of personal-vault workflows and supported data fields that later tickets can use without guessing.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Type:** research

**Work status:** open

- [ ] Compare the existing local application with the selected Vaultwarden web vault using Playwriter. Reuse existing tabs; do not open replacement tabs or enter passwords. Record locked-session limits instead of bypassing them.
- [ ] Do not reveal, copy, export, change, or log real credentials or live vault data. Use official documentation and synthetic examples where account inspection is unsafe or unavailable.
- [ ] Record reference version, client/deployment restrictions, evidence sources, observed behavior, and unverified claims in a stable named topic document.
- [ ] Define supported fields and validation semantics for Login, Card, Identity, Secure Note, and SSH Key; URI settings, custom field variants, history, folders, Trash, and JSON portability. Distinguish observation from proposed product behavior.
- [ ] Assign each candidate feature a disposition: core, follow-on, unsupported, or unverified. Do not equate local vaults with organizations or stored URI rules with autofill.
- [ ] Resolve enough of the supported JSON subset for later tickets to proceed using synthetic fixtures. Explicitly list remaining limits; do not claim full parity or invent delivery estimates.
