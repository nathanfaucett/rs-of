- **Authoritative ownership boundary (supersedes receipt 29):** Management owns Devices and endpoint IDs, including bindings, User ownership, approval/enrollment, transfer/revocation, restrictions and selections. IdP owns Users, credentials, Applications, OAuth Clients and token-signing trust, not Device/endpoint authority. Storage owns resources and consumes current Management endpoint authorization.
- **Endpoint ID is transport identity only.** Possession authenticates the endpoint, not permissions. Management approval and exact current Device/endpoint policy decide access; OAuth Principal, Device ID and token signer are distinct. Approved endpoints need no individual IdP signer/full Node enrollment. HTTPS/process count creates no Devices/Nodes or multi-endpoint aggregate, copied keys or per-service enrollment. Independent Storage uses its service Client/current Management policy, not its own endpoint key or duplicate policy store.
- Open/initialize each owner once per runtime; reuse handles for seed/import/serving. Fresh Create has no peer-history/content exchange and starts Storage/selection empty. Join imports only approved public state separately from resources. Opening stores is not three domain-enrollment ceremonies.
- Retain seed/key/Client/progress facts only for actual owner/security consumers. Bundled calls stay local without confidential service Clients or OAuth self-calls; independent relationships use authenticated HTTPS and protected consumer-local secrets. No cross-owner database opens, fixed historical Client count, distributed bootstrap transaction or compatibility migration.
- API hosts own lifecycle, not UI. One app supports web and desktop. Native capabilities reuse the shared worker; APIs do not serve a second frontend. Unified/desktop has one listener/prefix-once/shared endpoint/shutdown; independent owners keep separate addresses/lifecycles.
- Host-generated setup codes travel only to their exact owner in explicit Setup authorization, with durable exact intent/retirement and transient browser handling. TLS/Origin/loopback/first arrival alone is not admission. Source approval uses ordinary User permissions separately.
- Normal APIs always authenticate and authorize. Current readiness names concrete missing invariants; listener verification is not readiness or an auth-enable switch. Existing-only reopen is source-peer independent; remote policy still requires configured independent owner services.
- Both flows retain OS-level trust/verified HTTPS. Desktop handles native consent; web deployment arranges trust installation. Browsers cannot install OS trust or bypass TLS. Explicit reset deletes exact protected references before trust/data and never implies peer revocation/erasure; historical cleanup support is not migration.
- Measure Create/Join completion separately from acceptance, compilation and provider/trust costs. Preserve current checks and unchanged bounds. Operation-local batching is not an authorization cache; finite repeated passes are not a universal latency guarantee.
