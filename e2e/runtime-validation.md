## Changes

- Browser app login uses the existing public environment interface: explicit `PUBLIC_IDP_BASE_URL` plus `PUBLIC_OIDC_CLIENT_ID`, matching the selected IdP. It verifies live discovery issuer and token endpoint before enabling sign-in. It accepts HTTPS or HTTP loopback only. There is no seeded-server fallback.
- Tauri never takes this browser path, including a remote desktop selection. Existing independent setup observation and native capability handling remain. Production without explicit browser client configuration retains the independent setup path.
- Runner environments are separate: app password login uses `local-login`; password-manager uses its own seeded client. Both configure expected Application URIs. Password-manager's test scope is `openid profile email storage`; its existing default scope is unchanged.
- App Device requests now exchange for the configured Device audience, not `idp-management`. The shared exchange helper still restricts audiences to selected owners. The app's existing Application URI default remains unless explicitly configured.
- Password-manager passes an expected Application URI to its project-owned OIDC client. Identity binding remains enabled. Missing configuration fails closed with an actionable error.
- PKCE and session state use the SDK's existing local storage across full-page redirects. Root auth initialization handles the callback once; the callback no longer reinitializes and remounts itself.
- Sync uses the existing browser SDK export, not its Node root. Its effect belongs to the root component and tracks the verified User; SDK mutations are untracked to avoid effect loops.
- Vault database opening resolves the existing server-issued ID from the database list instead of sending `password-manager-main` as a UUID. Vite resolves the linked SQL package through `import.meta.resolve`, as the existing Vitest config does, so worktrees can serve its WASM.
- Restored seven unchanged native capability tests from before the first ticket05 commit. Extracted and restored pure registration trust-boundary/error tests without HTTP mocks. Ten browser-configuration tests guard explicit opt-in, unsafe issuers, desktop exclusion, and no seeded fallback. Total: 30 isolated tests.
- Ported all four deleted authorization page cases to real browser UI: missing registration, mismatched Application URI, malformed metadata for an existing server client, and a literal unknown client ID. Added server-name/scope/Allow/Deny assertions and actual denial with original state and no code exchange. Kept token, User info, vault selector, owner access, and reload assertions.
- CI runs the restored isolated suite and the separate real-backend app command. Existing serial real-backend lifecycle and failure reporting remain.

Complexity/risk: focused frontend fixes at existing configuration, OAuth, SDK and component lifecycle boundaries. Main risks are wrong service selection, identity confusion, and credential persistence; checks remain strict. No Rust, generated SDK, desktop lifecycle implementation, or unrelated unit test was deleted or changed.
