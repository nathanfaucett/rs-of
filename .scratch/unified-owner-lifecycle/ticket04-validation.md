Bundled actions retrieve `get_native_setup_code({owner})` separately, target-checked before and after retrieval; each HTTP request has one owner code and only IdP receives the password. Transient form secrets are cleared synchronously before awaiting protected retrieval/submission.
- Removed `WebSetupCreate`, `JoinSetup.svelte`, old DTOs/transport methods and topology-based source-approval dispatch. Both layouts use generated Device independent-join operations; sharing/copy/QR now supplies the full Device HTTPS base plus pinned endpoint, not a bare endpoint.
- Connection settings now collects Storage alongside IdP, Management and Device. `storageApiUrl.svelte.ts` persists only the nonsecret public base and validates its owner surface; onboarding consumes that selection rather than environment-only Storage.
- Native ticket02 already accepts an explicit owner for protected retrieval, prepares one CA and invokes stopped owner-local reset entry points. Those Rust paths were inspected, not reimplemented. Frontend now calls their current contracts. A desktop full reset remains a sequence of the three protected owner boundaries after close/join, with per-owner retained completion and shared CA preservation; no reset broker or HTTP reset endpoint was added.
- Removed the unused `idp-server::hosted_setup` implementation, exports and implementation-specific tests. The canonical exporter no longer merges its six obsolete routes/schemas/security scheme. Both IdP SDK families remove SetupApi and the seven old models; owner setup and existing domain APIs remain.
- Updated API gate to run the actual composition test by exact name instead of its removed filter; removed a zero-test obsolete Unified OpenAPI filter. Built exports explicitly reject the retired group/models.
- Reconciled glossary, README, API/route inventory, worker, security, operations, control-plane, public-persistence, native and affected context docs. Samples specify the required four composition prefixes, one HTTPS endpoint, owner-local roots/codes and no old host metadata/credential layout. Added the missing Device sample/recipe; removed the incompatible Unified HTTP Portless launcher. Standalone Management remains a policy-only HTTP backend requiring its configured HTTPS proxy, not another setup authority.
- No CLI provisioning/trust implementation was changed: its existing `--ca-path` pins a client root and Create/Join do not install OS trust. Documentation now names its actual four-base/three-code-file arguments and protected password file.
